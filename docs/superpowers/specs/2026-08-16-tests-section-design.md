# Розділ психологічних тестів

Дата: 2026-08-16

## Мета

Додати до сайту розділ із сімома психологічними скринінговими тестами. Розділ
працює на дві цілі одночасно:

- **SEO** — окрема сторінка на кожен тест приводить пошуковий трафік за запитами
  на кшталт «тест на тривожність», «тест EAT-26».
- **Лід-магніт** — людина отримує зрозумілий результат і бачить заклик записатися
  на консультацію.

## Обсяг

Сім тестів, усі — опубліковані валідовані методики у повних версіях:

| Слаг            | Тест на сайті                         | Методика                        | Питань |
| --------------- | ------------------------------------- | ------------------------------- | ------ |
| `anxiety`       | Тест на тривожність                   | GAD-7                           | 7      |
| `depression`    | Тест на депресію                      | PHQ-9                           | 9      |
| `ocd`           | Шкала Йеля-Брауна (ОКР)               | Y-BOCS, шкала тяжкості          | 10     |
| `dass21`        | Тривога, депресія та стрес            | DASS-21                         | 21     |
| `binge-eating`  | Тест на компульсивне переїдання       | BES (Binge Eating Scale)        | 16     |
| `attachment`    | Тест на тип прив'язаності             | ECR-R                           | 36     |
| `eat26`         | Тест на РХП                           | EAT-26 + 5 поведінкових питань  | 26 + 5 |

Поза обсягом: збереження результатів на сервері, особисті кабінети, надсилання
результату психологу, порівняння результатів у часі.

## Маршрути

Усі сторінки статичні (`generateStaticParams`).

- `/tests` — хаб: заголовок розділу, дисклеймер, сітка з семи карток
  (назва, кількість питань, орієнтовний час, для кого тест).
- `/tests/<slug>` — сторінка одного тесту.


Кожен файл тесту експортує один об'єкт `TestDefinition`. Додати восьмий тест —
це новий файл даних плюс рядок у реєстрі, без змін у рушії.

## Модель даних

```ts
type Choice = { label: string; value: number };

type Question = {
  /** Текст питання українською. */
  text: string;
  /** Свої варіанти відповідей. Якщо немає — беруться спільні для тесту. */
  choices?: readonly Choice[];
  /** Питання зі зворотним підрахунком (ECR-R, EAT-26 п.25). */
  reverse?: boolean;
  /** Питання-прапорець: не входить у бал, але впливає на результат. */
  flag?: 'crisis' | 'behavior';
};

type Band = {
  /** Верхня межа діапазону включно; діапазони перебираються по порядку. */
  max: number;
  label: string;
  tone: 'calm' | 'watch' | 'alert';
  /** 2–3 речення пояснення для людини. */
  text: string;
};

type Subscale = {
  id: string;
  title: string;
  /** Номери питань (з 1), які входять у підшкалу. */
  items: readonly number[];
  /** 'sum' — сума балів, 'mean' — середнє (ECR-R). */
  mode: 'sum' | 'mean';
  /** Множник підсумку: 2 для DASS-21, 1 для решти. */
  factor?: number;
  bands: readonly Band[];
};

type TestDefinition = {
  slug: string;
  /** Назва в хедері картки й у H1. */
  title: string;
  /** Назва методики, автори, рік — рядок під результатом. */
  source: string;
  metaTitle: string;
  metaDescription: string;
  /** Абзаци інтро, які рендеряться на сервері. */
  intro: readonly string[];
  /** Що саме людина оцінює: «за останні 2 тижні», «за останній тиждень». */
  timeframe: string;
  estimatedMinutes: number;
  /** Спільні варіанти відповідей, якщо у питань немає своїх. */
  choices?: readonly Choice[];
  questions: readonly Question[];
  /** Одна підшкала для сумарних тестів, кілька для DASS-21 і ECR-R. */
  subscales: readonly Subscale[];
  /** Тип прив'язаності за двома вимірами — лише для ECR-R. */
  quadrant?: {
    /** Межа «низький / високий» по кожному виміру. */
    threshold: number;
    /** Назва й опис типу для кожної з чотирьох комбінацій. */
    styles: Record<
      'lowLow' | 'highLow' | 'lowHigh' | 'highHigh',
      { label: string; text: string }
    >;
  };
};
```

Модель покриває чотири відмінності між методиками:

1. **Варіанти відповідей.** GAD-7, PHQ-9, DASS-21, ECR-R, EAT-26 мають спільну
   шкалу на весь тест. Y-BOCS і BES мають унікальні формулювання варіантів під
   кожним пунктом — вони задаються в `Question.choices`.
2. **Підшкали.** DASS-21 дає три результати по 7 питань, ECR-R — два виміри по
   18. Решта тестів має одну підшкалу з усіма питаннями.
3. **Перетворення балу.** `mode: 'mean'` для ECR-R, `factor: 2` для DASS-21,
   проста сума для решти. Зворотні питання рахуються як
   `minValue + maxValue - answerValue`, де межі беруться з варіантів
   відповідей цього питання (ECR-R: `8 - value`, EAT-26: `3 - value`).
4. **Питання-прапорці.** Не входять у бал, але змінюють результат:
   - `flag: 'crisis'` — 9-й пункт PHQ-9 про думки про самоушкодження. Ненульова
     відповідь показує вгорі результату блок із лінією запобігання самогубствам
     7333.
   - `flag: 'behavior'` — п'ять поведінкових питань EAT-26 (зриви, очищення,
     проносне, надмірні тренування, різка втрата ваги). Будь-яка позитивна
     відповідь показує окремий блок «поведінкові маркери» з рекомендацією
     звернутися до фахівця незалежно від сумарного балу.

## Підрахунок і діапазони

**GAD-7.** Сім питань, шкала 0–3 («Зовсім ні» / «Кілька днів» / «Більше
половини днів» / «Майже щодня»), період — 2 тижні. Сума 0–21.
Діапазони: 0–4 мінімальна тривога, 5–9 легка, 10–14 помірна, 15–21 тяжка.

**PHQ-9.** Дев'ять питань, та сама шкала 0–3, період — 2 тижні. Сума 0–27.
Діапазони: 0–4 мінімальна, 5–9 легка, 10–14 помірна, 15–19 помірно тяжка,
20–27 тяжка. Дев'ятий пункт додатково має `flag: 'crisis'`.

**Y-BOCS (шкала тяжкості, самозвіт).** Десять питань, кожне зі своїми п'ятьма
варіантами 0–4, період — останній тиждень. Сума 0–40. Дві підшкали:
обсесії (п. 1–5) і компульсії (п. 6–10). Діапазони загального балу: 0–7
субклінічний рівень, 8–15 легкий, 16–23 помірний, 24–31 тяжкий, 32–40 вкрай
тяжкий.

**DASS-21.** Двадцять одне питання, шкала 0–3, період — останній тиждень.
Три підшкали по 7 питань, підсумок кожної множиться на 2:

- Депресія — п. 3, 5, 10, 13, 16, 17, 21. Діапазони: 0–9 норма, 10–13 легка,
  14–20 помірна, 21–27 тяжка, 28+ вкрай тяжка.
- Тривога — п. 2, 4, 7, 9, 15, 19, 20. Діапазони: 0–7 норма, 8–9 легка,
  10–14 помірна, 15–19 тяжка, 20+ вкрай тяжка.
- Стрес — п. 1, 6, 8, 11, 12, 14, 18. Діапазони: 0–14 норма, 15–18 легкий,
  19–25 помірний, 26–33 тяжкий, 34+ вкрай тяжкий.

**BES.** Шістнадцять питань, кожне з трьома-чотирма власними варіантами з
вагами 0–3. Сума 0–46. Діапазони: до 17 — переїдання відсутнє або мінімальне,
18–26 — помірне, 27 і вище — виражене.

**ECR-R.** Тридцять шість тверджень, шкала 1–7 («Категорично не погоджуюсь» —
«Повністю погоджуюсь»), стосується близьких романтичних стосунків. Два виміри
по 18 пунктів: тривожність прив'язаності та уникання близькості. Результат
кожного виміру — середнє від 1 до 7. Зворотні пункти беруться з опублікованого
ключа Fraley, Waller & Brennan (2000) і звіряються з ним під час реалізації.

Тип прив'язаності визначається за серединою шкали (4.0) по двох вимірах:

- низька тривожність + низьке уникання → надійний
- висока тривожність + низьке уникання → тривожний
- низька тривожність + високе уникання → уникаючий
- висока тривожність + високе уникання → тривожно-уникаючий

**EAT-26.** Двадцять шість тверджень, шкала з шести варіантів («Завжди» —
«Ніколи»), що дають бали 3, 2, 1, 0, 0, 0; пункт 25 рахується у зворотному
порядку. Сума 0–78, поріг занепокоєння — 20 і вище. Додатково п'ять
поведінкових питань за останні 6 місяців із `flag: 'behavior'`.

## Досвід проходження

**Інтро.** Рендериться на сервері, тому індексується: H1, абзаци про те, що
вимірює тест і кому він корисний, рядок «21 питання · ~4 хвилини · за останній
тиждень», дисклеймер, кнопка «Почати».

**Проходження.** Одне питання на екран. Зверху — прогрес «7 / 21» і смужка.
Варіанти відповідей — великі кнопки на всю ширину. Вибір варіанта автоматично
переводить на наступне питання; є кнопка «Назад». Керування з клавіатури:
цифри 1–n обирають варіант, стрілки — переміщення по варіантах, Enter —
підтвердження. Розмітка — `fieldset` з `legend` і групою радіокнопок; зміна
номера питання оголошується через `aria-live="polite"`.

Прогрес зберігається в `sessionStorage` під ключем `test-progress:<slug>`, щоб
випадкове оновлення сторінки не з'їло 36 відповідей ECR-R. При відкритті
завершеного тесту пропонується почати заново.

**Результат.** Бал, горизонтальна шкала з позначкою поточного рівня, назва
рівня, 2–3 речення пояснення, підказка що робити далі, CTA «Записатися в
Telegram», кнопка «Пройти ще раз» і посилання на два суміжні тести. DASS-21
показує три шкали, ECR-R — два виміри плюс назву типу прив'язаності. Під
результатом — назва методики з авторами та дисклеймер про те, що це скринінг,
а не діагноз.

Кризовий блок (лінія 7333) показується вгорі результату, якщо спрацював
`flag: 'crisis'` або якщо бал потрапив у найтяжчий діапазон PHQ-9.

Анімації переходів між питаннями вимикаються при `prefers-reduced-motion`.

## Аналітика

Відповіді не залишають браузер. В аналітику йде лише діапазон результату.

- `Started Test` — `{ Test: '<slug>' }`
- `Completed Test` — `{ Test: '<slug>', 'Score Band': '<band id>' }`; для
  DASS-21 і ECR-R додаються діапазони кожної підшкали окремими властивостями
- Клік на CTA з екрана результату йде через наявний `trackTelegramClick` з новим
  джерелом `test_result` у типі `TelegramCtaSource`, тому ліди з тестів видно
  окремо в Amplitude, GA4 і Google Ads

Події віддзеркалюються в `window.gtag` за наявним у `lib/analytics.ts` шаблоном.
Конверсію Google Ads тести не надсилають — тільки клік по CTA, як і решта сайту.

## SEO

- Своя `metadata` з canonical `/tests/<slug>` на кожній сторінці; хаб — `/tests`.
- `app/sitemap.ts` додає вісім URL: хаб і сім тестів.
- JSON-LD: `<JsonLd />` зараз стоїть у `app/layout.tsx`, тому розмітка `FAQPage`
  з головної рендериться і на сторінках тестів — для Google це неправдиві
  структуровані дані. Компонент переїжджає в `app/page.tsx`. Сторінки тестів
  отримують власний JSON-LD типу `WebPage` з `BreadcrumbList`
  (Головна → Тести → назва тесту).

## Зміни в наявному коді

Розділ тестів — перші сторінки сайту поза головною, тому глобальна навігація
потребує правок:

- `navItems` і `footerSections` у `lib/content.ts` містять голі якорі (`#about`,
  `#pricing`). З `/tests/anxiety` вони нікуди не ведуть — стають `/#about` тощо.
- Те саме для посилань у нижньому рядку `Footer.tsx` і кнопки «Ціни» в
  `StickyCta.tsx`.
- У `navItems` і `footerSections` додається пункт «Тести» з посиланням `/tests`.
- `<JsonLd />` переноситься з `layout.tsx` у `app/page.tsx`.
- `TelegramCtaSource` у `lib/analytics.ts` отримує значення `test_result`.

## Приватність і юридичне

- Дисклеймер на хабі, на інтро кожного тесту та під результатом: це скринінговий
  опитувальник, а не діагноз; діагноз ставить лікар або клінічний психолог після
  очної оцінки.
- Явна фраза про те, що відповіді не зберігаються й не передаються, а в
  аналітику потрапляє лише знеособлений діапазон результату.
- Секція «Конфіденційність» на головній доповнюється абзацом про тести.
- Під кожним тестом — назва методики, автори й рік публікації.

## Тексти питань

Питання беруться з опублікованих версій методик і перекладаються українською:
звертання на «ви», формулювання адаптуються під зрозумілість без зміни змісту
пункту. Ключі підрахунку (номери зворотних пунктів, склад підшкал, ваги
варіантів) звіряються з першоджерелом під час реалізації — помилка в ключі дає
неправильний результат при формально правильному коді.

## Перевірка

- `npm run typecheck` і `npm run lint` проходять.
- Ручна перевірка кожного з семи тестів: крайні випадки — всі мінімальні
  відповіді та всі максимальні — дають очікувані граничні бали та діапазони.
- Перевірка кризового блоку: ненульова відповідь на 9-й пункт PHQ-9.
- Перевірка поведінкових маркерів EAT-26 при низькому сумарному балі.
- Перевірка прогресу в `sessionStorage`: оновлення сторінки посеред ECR-R
  зберігає відповіді.
- Клавіатурна навігація й читання екранним диктором на одному з тестів.
- Посилання глобальної навігації працюють зі сторінки тесту.
