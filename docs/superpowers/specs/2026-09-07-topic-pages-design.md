# Тематичні сторінки: кластер РХП, тривоги й підліткової терапії

Дата: 2026-09-07

## Мета

Сайт має одну змістовну сторінку — головну — і сім сторінок тестів. Усі запити,
з якими люди шукають психолога («терапія анорексії онлайн», «психолог панічні
атаки», «підлітковий психолог РХП»), зараз ведуть на один URL, який не відповідає
жодному з них окремо. У Google сайт видно лише за брендовими запитами; у
ChatGPT-пошуку його представляють каталоги (HoldYou, psihologi.top), а не власний
домен.

Ця спека описує перший підпроєкт із чотирьох, що дають реальний приріст
видимості: кластер із шести тематичних сторінок, кожна з яких відповідає рівно на
один намір пошуку. Це реалізація етапів 3 і 4 плану SEO (реєстр маршрутів,
мінімальний набір контенту на сторінку діагнозу).

Решта підпроєктів — інформаційні статті, сторінка «Про мене» з узгодженням фактів
у каталогах, насичення сторінок тестів текстом — отримують власні спеки після
цього і будуються поверх реєстру, описаного тут.

## Ключові рішення

| Рішення | Вибір | Причина |
| --- | --- | --- |
| Хто пише тексти | чернетки — агент з наявних матеріалів Крістель; правки й затвердження — Крістель | тонка сторінка гірша за відсутню; YMYL-тема вимагає голосу практика, а не переказу довідника |
| Кількість сторінок | 6: хаб РХП + анорексія, булімія, переїдання; тривога й панічні атаки; підлітки | окремі наміри пошуку для кожного розладу; тривога й ПА ділять аудиторію і текст |
| Адреси | плоскі англійські slug-и: `/eating-disorders`, `/anorexia`, `/bulimia`, `/binge-eating`, `/anxiety-and-panic-attacks`, `/teens` | збіг із конвенцією `/tests/anxiety`; ієрархія живе в даних і крихтах, не в URL |
| Архітектура | реєстр `lib/topics/*` + один динамічний маршрут `app/[slug]` | одне джерело для сторінок, sitemap, крихт, карток на головній, футера і `llms.txt`; повтор патерну `lib/tests` → `app/tests/[slug]` |
| Формат тексту | структуровані TS-об'єкти (секції з блоками), без MDX і HTML у рядках | одна система контенту з `lib/content.ts`; MDX можна додати як формат поля пізніше, не ламаючи реєстр |
| Публікація | прапорець `published` у реєстрі; чернетка не збирається і не потрапляє в жодну інтеграцію | сторінка виходить лише після явного «ок» Крістель; превʼю — через Vercel preview-деплой гілки |
| Перевірка контенту | `scripts/check-topics.ts`, без тестового фреймворку | у проєкті вже є такий патерн (`check-tests.ts`); інваріанти контенту мають ламати збірку |

## Обсяг

Шість сторінок, спільний компонент сторінки, реєстр, інтеграція реєстру в шість
точок сайту, скрипт перевірки, перерозмітка відгуків тегами, дата `updatedAt` для
всіх URL у sitemap.

Поза обсягом: інформаційні статті; сторінка «Про мене» і синхронізація фактів із
каталогами; насичення сторінок тестів; заміна rewrite-ів `/about → /` на справжні
сторінки; зміни в `Header`; окрема аналітика подій на нових сторінках (глобальна
аналітика працює як є); будь-які інші теми з акордеону «З чим я можу допомогти»,
що не мають своєї сторінки.

## Маршрути

| URL | Роль | `parent` |
| --- | --- | --- |
| `/eating-disorders` | хаб РХП: огляд трьох розладів, спільна логіка терапії | — |
| `/anorexia` | дочірня РХП | `eating-disorders` |
| `/bulimia` | дочірня РХП | `eating-disorders` |
| `/binge-eating` | дочірня РХП (компульсивне переїдання) | `eating-disorders` |
| `/anxiety-and-panic-attacks` | тривога, тривожні стани, панічні атаки | — |
| `/teens` | підліткова терапія і робота з батьками | — |

Обмеження на slug: не збігається ні з `sectionIds` у `next.config.ts` (`about`,
`certs`, `services`, …), ні зі статичними маршрутами (`tests`), ні з `testSlugs`.
Rewrite-и секцій мають пріоритет над динамічним маршрутом, тож поточна поведінка
`/about → /` не змінюється. `/binge-eating` і `/tests/binge-eating` — різні
шляхи, конфлікту немає.

## Модель даних

```ts
type TopicBlock =
  | { type: 'paragraph'; text: string }
  | { type: 'list'; items: readonly string[] }
  | { type: 'callout'; tone: 'info' | 'safety'; text: string };

type TopicSection = {
  id: string;            // якір, латиницею: 'symptoms', 'when-to-seek-help'
  heading: string;       // текст <h2>
  blocks: readonly TopicBlock[];
};

type TopicDefinition = {
  slug: string;
  title: string;         // <title>, ≤ 60 знаків
  description: string;   // meta description, ≤ 155 знаків
  h1: string;            // не дорівнює title дослівно
  lead: string;          // абзац під H1 — пряма відповідь на запит
  published: boolean;
  updatedAt: string;     // ISO-дата останньої змістовної правки, руками
  parent?: string;       // slug хаба для дочірніх РХП
  requiresSafetyNote: boolean;  // true для anorexia, bulimia, anxiety-and-panic-attacks
  sections: readonly TopicSection[];
  faq: readonly Accordion[];      // 3–5 питань, унікальних для теми
  reviewTags: readonly ReviewTag[];  // фільтр відгуків за Review.tags
  tests: readonly string[];       // slug-и з lib/tests
  ctaMessage: string;             // текст для telegramLink()
};
```

Обов'язкові секції у фіксованому порядку (перевіряє скрипт):

1. `symptoms` — Як це проявляється
2. `when-to-seek-help` — Коли варто звернутися
3. `therapy` — Як проходить терапія зі мною
4. `format` — Формат і тривалість
5. `today` — Що можна зробити вже сьогодні

Для дочірніх РХП між 1 і 2 додається `difference` — Чим відрізняється від інших
РХП — з посиланнями на сестринські сторінки. Для хаба між 1 і 2 — `types` — Які
бувають розлади харчової поведінки — з посиланнями на трьох дітей.

Callout із `tone: 'safety'` обов'язковий там, де `requiresSafetyNote: true`:
коли стан є невідкладною медичною ситуацією і куди звертатися. Розміщується в
секції `when-to-seek-help`.

### Зміна типу відгуку

```ts
// було
type Review = { quote: string; author: string; topic: string };
// стає
type ReviewTag = 'РХП' | 'Анорексія' | 'Булімія' | 'Переїдання' | 'Тривога'
  | 'Панічні атаки' | 'Підлітки' | 'Батьки' | 'Самооцінка' | 'Депресія' | 'МРО' | 'Булінг';
type Review = { quote: string; author: string; tags: readonly ReviewTag[]; rating: number };
```

Поле `topic: 'Булінг · вага · оцінка 5/5'` склеює тему й оцінку, фільтрувати по
ньому не можна. Теги — це водночас ключі фільтра й підписи для показу, тому
записані так, як мають виглядати на сторінці. Компонент `Reviews` рендерить
підпис як `${tags.join(' · ')} · оцінка ${rating}/5`, тож вигляд на головній не
змінюється. `TopicDefinition.reviewTags` має тип `readonly ReviewTag[]`.
Мапінг відгуків до тегів затверджує Крістель.

## Сторінка

`TopicPage` рендерить блоки в цьому порядку; перші два мають дати відповідь на
запит до скролу:

1. Крихти: `Головна · <h1 хаба> · <h1 теми>` для дочірніх; `Головна · <h1>` для
   решти. Дочірні завжди йдуть через хаб.
2. `<h1>` + `lead`.
3. `TopicToc` і `TopicBody`. Зміст завжди присутній: обов'язкових секцій
   мінімум п'ять, і список підтем у HTML корисний і читачу, і краулеру.
4. `TopicRelated`: для хаба — три дитини; для дочірньої — хаб і дві сестри; для
   тем без ієрархії — не рендериться. Анкор картки дорівнює `h1` цільової теми.
5. `TopicTests`: картки з `tests`, посилання на `/tests/<slug>`, підпис із
   `TestDefinition.summary`.
6. `Reviews` з `items`, відфільтрованими за `reviewTags`. Якщо збігів < 2 — блок
   не рендериться.
7. `Faq` з `items = topic.faq`.
8. `Pricing` з `ctaMessage`.

Метадані: `title`, `description`, `alternates.canonical: topicPath(slug)`,
`openGraph.type: 'article'`, `openGraph.url`. OG-зображення — глобальне.

Стилі: `TopicPage.module.css` у наявній системі CSS-модулів. Тіло — колонка
~68ch, відступи між абзацами, стиль списків і callout-ів. На сайті ще не було
довгого читаного тексту, тож це новий шар, а не переюз.

## Інтеграції

Жоден файл, крім `lib/topics/*`, не знає списку тем. Шість читачів реєстру:

| Файл | Що робить |
| --- | --- |
| `app/sitemap.ts` | додає `publishedTopics()`: хаб `priority 0.8`, решта `0.7`; `lastModified` = `updatedAt` |
| `lib/jsonLd.ts` → `buildTopicJsonLd(topic)` | `@graph`: `WebPage` (з `about: { @type: 'MedicalCondition', name }` для діагнозів), `BreadcrumbList`, `FAQPage` з `topic.faq` |
| `components/Topics.tsx` | акордеон стає списком карток; пункти, що мають опубліковану сторінку, — посилання з анкором = `h1`; решта — текст без посилання |
| `components/Footer.tsx` | нова колонка «З чим працюю» з опублікованими темами |
| `app/llms.txt/route.ts` | розділ «Теми»: `title`, `lead`, URL і FAQ кожної опублікованої теми |
| `app/[slug]/page.tsx` | `generateStaticParams` з `publishedTopics()`; `dynamicParams = false` |

`app/robots.ts` не змінюється.

Неопублікована тема не потрапляє в жодну з шести точок і віддає 404. Для превʼю
використовується Vercel preview-деплой feature-гілки, де прапорець уже `true`.

Схема `MedicalWebPage` не використовується навмисно: вона тягне очікування
`reviewedBy`/`lastReviewed` від медичного рецензента, яких на сайті немає.

## Контент

### Джерела

Лише матеріали, що вже є від Крістель: тексти головної (`topics`, `services`,
`about`, FAQ), інтро й дисклеймери тестів, її анкети на HoldYou, psihologi.top і
qui.help, теми відгуків. Симптоматика й критерії — з відкритих описів МКХ-11 і
DSM-5 у переказі побутовою мовою, без цифр поширеності, без обіцянок результату,
без назв ліків. Кожне твердження — або її досвід, або загальновідоме.

### Вимоги до опублікованої сторінки

- `lead` + `sections` ≥ 800 слів; хаб — ≥ 1000.
- Усі обов'язкові секції присутні й у заданому порядку.
- У кожній секції є хоч одне речення від першої особи.
- 3–5 FAQ, унікальних для теми; нормалізоване питання не збігається з FAQ головної
  та інших тем.
- `title` ≤ 60, `description` ≤ 155 знаків, `h1 !== title`.
- Callout безпеки там, де `requiresSafetyNote`.
- `reviewTags` дають ≥ 2 відгуки.
- Кожен slug у `tests` існує; `parent` вказує на існуючу тему.

### Процес

1. Чернетки шести тем пишуться в `lib/topics/*.ts` з `published: false`, кожна —
   окремий коміт у feature-гілці.
2. Vercel preview-URL передається Крістель; правки приходять текстом або в
   Google Doc і вносяться в реєстр.
3. `published: true` — окремий коміт після явного «ок» на конкретну сторінку.
4. Черга: хаб РХП → анорексія → булімія → переїдання → тривога й ПА → підлітки.
   Хаб перший, бо на нього посилаються дочірні.
5. Мапінг відгуків до тегів іде на затвердження разом із першою сторінкою.

## Зміни в наявному коді

- `lib/content.ts`: `Review.topic` → `tags` + `rating`; словник тегів;
  `reviews` перерозмічено.
- `components/Reviews.tsx`, `components/Faq.tsx`, `components/Pricing.tsx`:
  необов'язкові пропси `items` / `heading` / `ctaMessage` з дефолтами, що
  дорівнюють поточним глобальним даним. Поведінка головної не змінюється.
- `components/Topics.tsx`: акордеон → картки з посиланнями на опубліковані теми.
- `components/Footer.tsx`: колонка «З чим працюю».
- `app/sitemap.ts`: `lastModified` з `updatedAt` замість `new Date()` для всіх
  URL. Для головної — константа `site.updatedAt` у `lib/site.ts`; для тестів —
  нове обов'язкове поле `TestDefinition.updatedAt` (по одній даті в кожному
  `lib/tests/*.ts`).
- `lib/jsonLd.ts`: `buildTopicJsonLd`; хелпер крихт виноситься зі
  `buildTestJsonLd` і переюзується.
- `app/llms.txt/route.ts`: розділ «Теми».
- `package.json`: скрипт `check:topics`.

## Перевірка

`scripts/check-topics.ts` (`npm run check:topics`) проганяє інваріанти з розділу
«Вимоги до опублікованої сторінки» по реєстру і завершується ненульовим кодом при
порушенні. Перевірки slug-ів, `parent`, `tests`, порядку секцій і callout-ів —
для всіх тем; перевірки довжини тексту, FAQ і відгуків — лише для
`published: true`, щоб чернетки не блокували роботу.

Ручна перевірка перед мерджем кожної опублікованої сторінки:

- `curl` HTML без JS містить H1, `lead`, усі H2 і текст FAQ;
- JSON-LD проходить Rich Results Test без помилок;
- `npm run build`, `npm run lint`, `npm run typecheck`, `npm run check:topics`
  чисті;
- Lighthouse SEO = 100, мобільний LCP не гірший за головну;
- сторінка є в `/sitemap.xml` і `/llms.txt`;
- крихти й перехресні посилання ведуть на існуючі URL.

## Критерії успіху

Оцінюються через 8–12 тижнів після публікації всіх шести сторінок:

- усі шість URL у стані «Проіндексовано» в Google Search Console;
- небрендові запити («психолог РХП», «терапія анорексії онлайн», «панічні атаки
  психолог») дають покази в GSC — зараз їх нуль;
- ChatGPT-пошук на запит виду «психолог з РХП в Україні онлайн» цитує сторінку
  теми, а не лише каталоги.

## Подальші кроки (не зараз)

Після публікації кластера — окремі спеки на: інформаційні статті, що посилаються
на теми; сторінку «Про мене» й узгодження фактів у каталогах; насичення сторінок
тестів текстом із посиланнями на відповідні теми. Розділення тривоги й панічних
атак на дві сторінки — лише за даними GSC, якщо запити розійдуться.
